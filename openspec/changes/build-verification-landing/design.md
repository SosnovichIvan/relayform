## Context

У Relayform уже есть Foundations: тёплые нейтрали, жёлтый primary action, коралловый signal-акцент, semantic variables и типографика Inter. Пользователь выбрал компактный эскиз `B / Verification first` и хочет развить его в лендинг без адаптивности.

## Goals / Non-Goals

**Goals:**

- Сделать две сопоставимые desktop-композиции: Light и Dark.
- Сохранить смысл выбранного направления: доверие к заявке через подтверждённые e-mail и телефон.
- Построить последовательность: header → hero → принцип работы → преимущества → финальный CTA → footer.
- Использовать auto layout, существующие semantic variables и text styles.

**Non-Goals:**

- Адаптивные брейкпоинты, мобильный макет, реализация на Next.js/Tailwind, сложные иллюстрации, pricing, выдуманные интеграции или кликабельный прототип.

## Decisions

- Разместить два самостоятельных desktop-фрейма рядом: каждый шириной 1440 px. Это даёт прямое сравнение тем и не требует искусственно дублировать содержимое в одной композиции.
- Сохранить исходную карточку `B / Verification first` рядом с финальными экранами как reference, а эскиз A удалить.
- Hero использует основной сценарий верификации как демонстрационную карточку: e-mail и телефон получают подтверждённые статусы. Это раскрывает продукт без неподтверждённых технических деталей.
- Primary CTA получает жёлтую роль. Коралл остаётся только небольшим signal-акцентом, а не вторым акцентным цветом.

## Risks / Trade-offs

- [Без адаптивности отдельные desktop-фреймы не доказывают удобство на маленьких экранах] → оформить это как отдельный будущий change после утверждения desktop-направления.
- [Контент может потребовать уточнения продукта] → пока использовать только уже подтверждённые возможности: доставка форм и e-mail/phone verification.

Изменения ограничены Figma. Откат: удалить новые фреймы Landing по их точным именам и вернуть эскиз A из истории версий Figma при необходимости.
