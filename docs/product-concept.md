# Концепция Relayform

## Проблема

Заявки с лендингов часто теряются: письмо попадает в спам, CRM не настроена, а менеджер не видит новый лид вовремя. При этом подтверждение контактов приходится реализовывать отдельно, повторяя интеграции с почтовыми и SMS-провайдерами.

## Решение

Relayform принимает события с сайта через единый API и доставляет их в выбранные каналы. В рамках того же проекта клиент подключает подтверждение e-mail и телефона.

## Сценарий отправки заявки

Клиент создаёт проект в кабинете, подключает один или несколько каналов и получает API-ключ. Его лендинг отправляет `POST /v1/events` с данными формы. Сервис возвращает идентификатор события, а пользователь получает уведомление с полями заявки и ссылкой на карточку события.

## Сценарий верификации

Приложение вызывает API подтверждения контакта. Relayform создаёт короткоживущую проверку, отправляет одноразовый код или ссылку, принимает подтверждение и возвращает статус `verified` либо `failed`.

## Принципы MVP

- Единая модель события вне зависимости от канала доставки.
- Каналы подключаются отдельно для каждого проекта.
- Секреты каналов и API-ключи хранятся зашифрованными.
- Доставка выполняется асинхронно с ограниченными повторами.
- Верификация ограничивается частотой запросов и сроком жизни кода.

## Важные ограничения

Интеграции с MAX, WhatsApp, VK и операторами телефонных сообщений требуют использования официальных API, одобрений и соблюдения их правил. Конкретные возможности подтверждения телефона зависят от выбранного провайдера и страны отправки.
