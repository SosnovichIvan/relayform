# Концепция Relayform

## Проблема

Заявки с лендингов часто теряются: письмо попадает в спам, CRM не настроена, а менеджер не видит новый лид вовремя. При этом подтверждение контактов приходится реализовывать отдельно, повторяя интеграции с почтовыми и SMS-провайдерами.

## Решение

Relayform принимает данные форм обратной связи и заявок с сайта через единый API и доставляет сообщение в выбранные каналы. В рамках того же проекта клиент при необходимости подключает подтверждение e-mail и телефона.

## Сценарий отправки заявки

Клиент создаёт проект в кабинете, выбирает один или несколько сервисных каналов Relayform и подтверждает адресата: запускает бота, разрешает сообщения, подтверждает номер или e-mail. Его сайт отправляет `POST /v1/events` с данными формы обратной связи или заявки. Сервис возвращает идентификатор события, а клиент получает уведомление с введёнными полями и ссылкой на карточку события.

## Сценарий верификации

Приложение вызывает API подтверждения контакта. Relayform создаёт короткоживущую проверку, отправляет одноразовый код или ссылку, принимает подтверждение и возвращает статус `verified` либо `failed`.

## Принципы MVP

- Единая модель события вне зависимости от канала доставки.
- Адресаты подключаются отдельно для каждого проекта; аккаунты и service credentials каналов принадлежат Relayform.
- Сервисные credentials шифруются; project API keys хранятся только как hash.
- Доставка выполняется асинхронно с ограниченными повторами.
- Верификация ограничивается частотой запросов и сроком жизни кода.

## Важные ограничения

Интеграции с MAX, VK и операторами телефонных сообщений требуют использования официальных API, одобрений и соблюдения их правил. Конкретные возможности подтверждения телефона зависят от выбранного провайдера и страны отправки.
